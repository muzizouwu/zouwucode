# ZOUWUCODE 打断功能使用说明

## 功能概述

打断功能允许用户在 AI 任务执行过程中随时中断当前任务，并通过"继续 / 放弃"两种方式恢复。
该功能覆盖全部三个交互端（CLI / TUI / WebUI），且与模式切换、缓存、会话、hello-my-zouwucode
模块等现有功能完全兼容。

## 一、触发方式

| 端 | 触发方式 | 确认机制 |
|----|---------|---------|
| TUI | `Esc` 快捷键（任务执行中随时可按；空闲时 Esc 仍为聚焦输入框） | 弹出确认对话框（Enter=确认打断 / Esc=继续执行） |
| WebUI | 输入框旁的 **⏹ 打断** 按钮（仅任务执行中显示），或 `Esc` | 浏览器原生 confirm 对话框 |
| CLI | 任务执行中按 `Ctrl+C` | 中断后显示恢复选项（误按可通过「继续」无损恢复） |

> 说明：TUI 与 WebUI 在打断前都有明确的确认步骤，防止误操作；CLI 的 Ctrl+C 是
> 终端即时信号（按下即中断当前等待），因此通过中断后的恢复选项弥补误按风险。

## 二、打断的安全点

打断请求发出后，任务会在**最近的安全点**停止（约 0.1 秒内生效），安全点包括：

1. **LLM 流式响应期间** — 每个 chunk 到达时检查，长文本生成可即时停止
2. **工具轮次边界** — 每轮 LLM 请求结束后
3. **工具执行前** — 每个工具调用开始前检查，不会把工具执行到一半

打断生效后，引擎底层挂起的 LLM 网络流会被同步取消，不会留下后台孤儿连接。

## 三、中断后的状态保障

- **会话上下文合法**：如果中断发生在工具调用序列中间，引擎会为未执行的
  工具调用补写 `[interrupted by user]` 合成结果，保证对话前缀（prefix cache）
  依然符合 API 消息配对规则 — 中断后可以直接发起新请求，不会报错。
- **中断信号自动复位**：每次任务结束（无论正常完成、超时、打断）中断信号都会
  清零，连续多次打断不会污染后续任务。
- **会话日志**：中断事件会写入会话日志（`[interrupted]` 标记），便于事后追踪。

## 四、恢复选项

任务被打断后，界面会显示明确的恢复提示：

| 选项 | 操作 | 效果 |
|------|------|------|
| **继续任务** | 直接输入「继续」或「continue」 | AI 看到中断前的完整上下文（含已执行的工具结果和未执行的标记），从断点接着做 |
| **放弃任务** | TUI/WebUI 输入 `/clear` 清空对话 | 丢弃本轮上下文，重新开始 |

## 五、界面状态提示

| 阶段 | TUI 状态栏 | WebUI 状态栏 |
|------|-----------|-------------|
| 执行中 | `Processing... (Esc 打断)` | `Processing... (Esc 打断)` + ⏹ 按钮显示 |
| 已确认打断 | `Interrupting... (等待任务停止)` + 聊天区黄色提示 | `Interrupting... (等待任务停止)` |
| 已打断 | `Interrupted (已打断 — 可输入「继续」恢复)` + 恢复选项框 | `Interrupted` + 恢复提示消息 |
| 空闲时按 Esc | 聚焦输入框（保持原有行为） | 按钮隐藏，无法触发 |

## 六、接口说明（WebUI）

新增 `POST /api/interrupt`：

```json
// 任务执行中 → 200
{"interrupting": true}

// 无任务执行中 → 409
{"interrupting": false, "message": "当前没有正在执行的任务"}
```

`GET /api/status` 新增字段 `"running": true/false`，可用于前端实时显示任务状态。

SSE 流式接口 `/api/chat/stream` 新增事件类型：

```json
{"type": "interrupted", "message": "Task interrupted by user ..."}
```

## 七、异常处理

- **打断请求失败**（如引擎内部异常）：界面显示红色错误信息，任务不受影响继续执行
- **空闲时误触**：TUI 显示黄色提示；WebUI 返回 409 + 说明信息
- **重复按打断键**：TUI 防抖（打断等待期间不重复弹窗）；引擎层面 `request_interrupt` 幂等
- **连续打断**：中断事件在任务结束时自动复位，经测试连续打断循环不产生状态残留
- **CLI 强制退出语义保留**：无任务执行时 Ctrl+C 仍提示 `(Use /exit to quit)`，不改变退出习惯

## 八、架构实现（开发者参考）

```
┌──────────┐  request_interrupt()   ┌─────────────────────┐
│ TUI/WebUI │ ─────────────────────▶ │ EngineLoop           │
│ (确认弹窗) │                        │ threading.Event      │
└──────────┘                        └─────────────────────┘
                                           │ 安全点检查（0.1s 轮询 + chunk 检查）
                                           ▼
                                    TaskInterrupted 异常
                                           │
                              ┌────────────┴────────────┐
                              ▼                         ▼
                     清理 prefix（合成 tool 结果）    取消孤儿网络流
                              │
                              ▼
                     UI 捕获 → 显示恢复选项
```

核心代码位置：
- 引擎打断核心：`zouwucode/engine/loop.py`（`request_interrupt` / `TaskInterrupted` /
  `_run_interruptible` / `_cleanup_interrupted_prefix` / `cancel_pending_io`）
- TUI 确认弹窗与快捷键：`zouwucode/tui/textual_app.py`（`InterruptConfirmScreen` /
  `action_interrupt`）
- CLI Ctrl+C 处理：`zouwucode/tui/app.py`（`run_interactive`）
- WebUI 按钮/接口/SSE：`zouwucode/webui/server.py`（`/api/interrupt` /
  `interruptTask()` / `TaskInterrupted` 捕获）
- 测试用例：`tests/test_interrupt.py`（19 个用例：正常中断 / 异常中断 / 连续中断 / 状态稳定 / 三端接线）
